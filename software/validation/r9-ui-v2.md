# R9 UI 显示层 2.0.0 验证记录

记录日期：2026-11-20。验证对象为验证板「ESP32S3 功能板 TFT版」，MCU 为 ESP32-S3-WROOM-1-N16R8，MAC `64:E8:33:7F:4D:B4`，串口 COM4。

## 一、屏幕规格的确认过程

PDF 只提供原理图，直接按文本流提取会丢失连线位置。初版按引脚编号正序推断出 `SCL=IO9, SDA=IO10, RES=IO11, DC=IO12, CS=IO21, BLK=IO38`，据此驱动屏幕全程无反应。

改用 300 dpi 渲染原理图 PDF 后，U2 的连线与标注可以直接读出：

| U2 引脚 | 信号 | 实际网络 |
| --- | --- | --- |
| 8 | BLK | IO9 |
| 7 | CS | IO10 |
| 6 | DC | IO11 |
| 5 | RES | IO12 |
| 4 | SDA | IO21 |
| 3 | SCL | IO38 |
| 2 | VCC | 3V3 |
| 1 | GND | GND |

同图内标注 `128*160 1.8寸TFT`，即面板为 1.8 英寸、128×160、8 脚 SPI，横屏安装后可视区为 160×128。此前按 240×320 设计的高分辨率版式不适用于本面板。

## 二、硬件层排查

按修正后的引脚重新驱动，屏幕仍无输出。逐项排除：

| 假设 | 方法 | 结果 |
| --- | --- | --- |
| 引脚顺序错 | 按原理图渲染结果改正 SCL/SDA/RES/DC/CS/BLK | 无像素变化 |
| 背光极性反 | IO9 交替高/低各 3 秒，同时保持白屏输出 | 屏幕亮度无变化 |
| 背光在其它引脚 | 依次把 IO3/4/5/6/7/8/1/38/39/40/41/42/47/48 拉高 2.5 秒 | 14 个引脚均未点亮背光 |
| SPI 速率过高 | 40 MHz 降至 1 MHz | 无像素 |
| 控制器不匹配 | ST7735、ST7789、ILI9341 三套初始化表分别初始化为 128×160、240×320 | 均无输出 |
| 读回控制器 ID | 把 SDA 临时切为输入，软件时序发 RDDID/RDDST/RDDPM/RDDMADCTL/RDDCOLMOD/RDID1-3 | 全部返回 `0xFF`，SDA 为单向输入 |

最后一项说明该模块的 SDA 只接屏的 SDI，无法读回。综合判断：屏幕模块未进入工作状态，问题位于模块插接或供电，不在固件侧。

面板以插针连接在主板排母上，可用肉眼检查是否插到底、有无错位。

## 三、固件侧结果

- 编译：`esp32:esp32:esp32s3`，FlashSize=16M、PSRAM=opi、PartitionScheme=app3M_fat9M_16MB。
- 应用占用 1,600,438 字节，为 3 MB 分区的 50.9%；静态变量 51,484 字节，为 15%。
- 默认 1.25 MB 分区编译失败（122%），原因是 12 px 与 16 px 两套 GB2312 点阵合计约 516 KB。
- 自研板（不带 `-DBOARD_VERIFY`）与验证板两份配置均通过编译。

## 四、界面版式的核对方式

屏幕不可见期间，用与设备端相同的度量在主机端出图，逐页核对折行、间距与选中态。核对依据来自线上题库的真实文本：40 道题的选项长度为 1–8 个字符，中位数 3，因此题目页按短选项优先排版，长选项走折行与滚动兜底。

已核对并修正的问题：

1. 选项文字超出卡片下边界 —— 改为按实际行数计算行高。
2. 240×320 版式的题干加四个双行选项超出可视区 —— 引入滚动视口与右侧滚动条。
3. 160×128 下菜单标题压住首行 —— 菜单页不再单独占标题行，改为按可用高度决定可见行数。
4. 底栏文字被裁切 —— 度量改为按短边分档，标题、正文、底栏各自留出基线余量。

## 五、尚未验证的部分

- 实机像素输出、背光亮度、颜色方向与显存偏移，须待屏幕恢复后用摄像头逐页比对。
- 7 个按键的实际键位与手感，其中验证板用 BOOT(IO0) 补第 7 键，上电期间不可按住。
- 验证板的 A/B 两路与舵机映射到 IO4/IO5/IO6 的板载 LED，仅能反映占空比，无法验证功率级。
- Wi-Fi 配网、题库取题与提交、ThingsCloud 双向同步在验证板上的端到端表现。协议部分沿用 1.4.0，本轮未改动。
- 1.8 寸面板在 128×160 下的实际可读性，尤其 12 px 汉字与 7 px 提示文字。
