# R9 UI 2.0 屏幕点亮与调试记录

记录日期：2026-11-21。对象为「ESP32S3 功能板 TFT版」验证板。本文按发现顺序记录问题、误判与最终结论，供后续复现时少走弯路。

## 一、验证板硬件参数

| 项目 | 参数 |
| --- | --- |
| MCU | ESP32-S3-WROOM-1-N16R8（16 MB Flash / 8 MB OPI PSRAM） |
| MAC | `64:E8:33:7F:4D:B4` |
| 串口 | CH340K，COM4，115200 |
| 屏幕 | 1.8 英寸 128×160 ST7735S，8 脚 SPI，横屏安装后可视区 160×128 |
| 屏幕连接 | FPC 排线压接，不是排针排母 |
| 按键 | 6 个轻触键 IO13–IO18，另有 BOOT 键 IO0 可补第 7 键 |
| 温湿度 | DHT11，DATA 接 IO8 |
| 模拟量 | 无 MQ-2 / MQ-135；IO1 为光敏电阻 |
| 板载 | 4 个 LED（IO4–IO7）、WS2812（IO48）、蜂鸣器（IO47）、继电器（IO2） |

## 二、踩过的坑

### 坑 1：从 PDF 文本流推断引脚，顺序全反

用 PDF 文本提取拿到的引脚序列是按阅读顺序输出的，与原理图上的连线和引脚编号没有对应关系。据此得出 `SCL=IO9, SDA=IO10, RES=IO11, DC=IO12, CS=IO21, BLK=IO38`，与真实接法几乎完全错位。

**教训**：原理图必须渲染成图片按图读线，不能依赖文本提取的结果做电气判断。

### 坑 2：把屏幕规格误判为 240×320

早期按「高分辨率全彩」的预期设计了 240×320 版式，实际面板是 128×160。整套版式需要按 160×128 重做，字号、行数、信息密度全部改变。

**教训**：动手排版之前先确认物理分辨率，宁可先做一次纯色填充验证。

### 坑 3：背光不亮被当成「屏幕没供电」

第一块板背光完全不亮，据此判断模块无供电。换板后背光正常，说明第一块板确有问题，但当时无法区分「模块坏」与「接线错」，在两块板之间反复试错浪费了大量时间。

**可复用的判据**：ST7735 模块的背光 LED 经限流电阻直接接 VCC，没有使能脚。只要模块有 3.3 V，背光必然发亮，任何固件都关不掉。**背光不亮 = 模块没电**，可以直接跳到硬件检查，不必再试驱动。

### 坑 4：SPI 重复 `begin()` 不切换引脚，制造了「多组都能工作」的假象

这是最误导人的一个。扫描固件逐组调用 `SPI.begin(scl, -1, sda, -1)`，看起来每组都重新配置了引脚。实际上连续调用时引脚映射并未真正切换，屏幕上出现的多种颜色**始终是用第一次配置的那组引脚画出来的**。

由此产生了两个错误结论：

1. 「交换 SCL/SDA 也能工作」——不可能，是假象。
2. 「引脚是 21/38」——实际是第一次配置的 38/21。

**破解方式**：写一个只初始化一次、只换颜色的固件。单次初始化下能正常出红绿蓝，才说明这组引脚成立。

**教训**：ESP32 的 `SPI.begin()` 不要重复调用。需要切换引脚时，先 `end()`，或用独立的 `SPIClass` 实例，或干脆每次上电只配置一次。

### 坑 5：为「提高稳定性」降频，反而破坏了时序

看到画面闪烁，把 SPI 从 20 MHz 降到 8 MHz、再降到 1 MHz，结果完全不出图。真正原因是引脚接错，降频只是让错误更难被发现。

**教训**：闪烁优先怀疑接触与引脚，不要先动频率。频率应作为独立变量单独验证。

### 坑 6：拿另一块板的示例代码套用

《点菜代码》用的是 `CS=15, RST=21, DC=2, SCK=14, MOSI=13`，那是另一块 ESP32 点菜器的接法，与这块 S3 功能板无关。盲目套用等于多试了一组无效组合。

**教训**：示例代码只在确认是同一块板时才有参考价值。屏幕型号相同不代表引脚相同。

### 坑 7：小字号行高超过容器高度，底栏被裁

`FontCN` 对 12 px 以下的字号统一返回 14 px 行高，而底栏高度只有 13 px。排版按 `(容器高 - 行高) / 2` 居中，结果文字被裁掉下半截。

**修复**：底栏改用固定基线偏移，不再按行高居中。

### 坑 8：配网页行距按大屏计算，内容溢出屏幕

按 240×320 的行距排 5 行内容，在 128 高度的屏上溢出约 28 px，最后一行「浏览器打开」被底栏盖住。

**修复**：压缩为 5 行、行距 17 px，把地址与 MAC 合并到底部。

### 坑 9：标签与数值的横向偏移不足，文字重叠

「连接热点」四个汉字占 48 px，而数值起点只偏移 40 px，两者叠在一起。**修复**：偏移改为 54 px。

## 三、可复用的排查方法

1. **单变量对照**：每次只改一个因素（引脚、频率、初始化表），并保留上一次能工作的版本做对照。
2. **静帧测试**：只画一次、不再刷新，用于区分「通信不稳」与「刷新逻辑有问题」。
3. **硬件 SPI 与软件时序各测一次**：软件时序完全绕开 SPI 外设，若不工作则问题在硬件层。
4. **复位白闪是正常现象**：每次重新初始化屏幕会短暂变白，不是故障。
5. **背光判据**：背光不亮直接查供电，不要试驱动。
6. **一次只初始化一次 SPI**：这条能避免一大类假象。

## 四、最终可用参数

```
SCL=IO38  SDA=IO21  CS=IO10  DC=IO11  RES=IO12  BLK=IO9
控制器   ST7735S
分辨率   128x160，rotation=1 时为 160x128
SPI      20 MHz，MODE0
初始化   SWRESET → SLPOUT → FRMCTR1/2/3 → PWCTR1-5 → VMCTR1
         → MADCTL(0x60 横屏) → COLMOD(0x05) → 伽马 → DISPON
```
