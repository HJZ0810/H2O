## 编译与烧录

使用 Arduino ESP32 Core **3.3.12** 和仓内 `software/libraries`。在仓库根目录按实际用途运行，例如：

```powershell
.\software\tools\build-r10.ps1 -Target handheld -Board yd2540
.\software\tools\build-r10.ps1 -Target monitor -Board yd2540
```

TFT 功能验证板使用 `-Board verify`。该板的光敏器件和 LED 只用于验证，MQ-2、MQ-135、风扇和 SG90 的课程验收需使用实际器件。R10 适配 N16R8、16 MB Flash、OPI PSRAM、3 MB 应用分区。每个附件子目录包含本次编译器生成的 `flash_args`、启动程序、分区表、boot_app0 与应用程序。对照实际串口，先断开外部供电和执行负载。使用配套 esptool 执行 `write-flash @flash_args` 时，工作目录选对应固件子目录。实板复核型别与分区后再操作。保留现有配置时无需全片擦除。

## MQTT、执行器与传感器

- 任务 A 走课程 MQTT。任务 B 走 24014 抽中的 **OneNET**。迁移产品物模型时，将 `fan_level` 和 `servo` 均设为读写。支持直接整数和含 `value` 的对象。风扇可设 0–100%，舵机指令可设 0–180°。
- 综合手柄把云端角度换算为舵机驱动的归一化位置。进入手动风扇页面、手动停机及关闭云监测会断开自动控制。选择本地控制后，需要再次开启云监测才能恢复远程下发。
- SG90 云端显示的是指令角度。实际转角需要装配后限位校准。综合手柄保留了原驱动的保守行程，独立监测固件使用独立的舵机脉宽范围。先脱开负载再核实两端行程。
- MQ-2 与 MQ-135 使用 ADC 电压折算的相对量 **0–1000**。与旧 OneNET 产品对接时，更新属性单位和面板图例。要填写 ppm 需补充探头预热、标定和气体种类记录。超过有效采样范围的综合手柄读数不会上报。
- 独立固件在 Wi-Fi 初次未连上时仍可采样和运行本地联动，网络恢复后可重新接入 MQTT。OneNET 下发等待实际驱动成功后才返回成功码。换密、迁移已有设备及云后台物模型更新需要现场运维窗口。

### 传输配置

课程规定的连接参数与 OneNET 设备密钥分开配置。OneNET 的 MQTT 密码使用设备密钥签发的一小时 token。生产 TLS 接入可在当前固件目录新建 `OneNetTrust.h`，定义 `H2O_ONENET_CA` 为所用产品端点的官方 PEM 信任锚。构建使用 8883，证书校验失败时连接失败。未提供该头文件的候选二进制兼容原项目 1883 明文接入，优先在受控网络验收。已配置 MQTT 镜像的旧设备需要单独轮换历史共享凭据。

综合手柄的可选镜像从本地 `MirrorLocal.h` 读取 `H2O_MIRROR_DEVICE`、`H2O_MIRROR_HOST`、`H2O_MIRROR_PORT`、`H2O_MIRROR_USER`、`H2O_MIRROR_PASS` 和 `H2O_MIRROR_CA`。其用途是向授权 TLS broker 发布遥测。公开附件采用无镜像凭据的默认构建，自建实时通道需用自己的证书和账号重新构建。面向 OneNET 的设备端控制继续使用 OneNET 的设备身份。

## 首件验收顺序

1. 用卡尺量两排针**中心距**，比对 J1/J2 方向和十芯 IDC 针 1。核对 SG90 安装件、天线前方净空、板上各接口和四角支撑。
2. 分阶段上电，记录空载、风扇起动和舵机动作时的 5 V 与 3.3 V 最小值，观察复位和异常自启。安装扇叶前先检查电机、舵机和本地停止功能。
3. 任务 A 使用本组实物完成手动作答，并保存课程服务器回执。任务 B 在 OneNET 后台保存三种传感器的时间序列及两个执行机构的下发、回读与实物响应。
4. 按[课程评分表](requirements.md)补记录。提交包含九章报告的 DOCX/PDF、5–8 分钟演示视频、实物照片、工程源文件和组员分工。
