# R10 硬件缺陷与勘误（现场实测）

> 记录日期 2026-11-25。全部结论来自 PCB1 首件焊接通电实测，配合 R10 制造基线飞针网表
> （`hardware/R10/gerber-baseline/wide-PCB1-after-silk-gerber.zip`）逐脚核对。
> 标 **致命** 的项会导致该路功能完全不可用，且存在损坏外设的风险。

## 汇总

| 编号 | 位置 | 严重度 | 一句话 | 状态 |
|---|---|---|---|---|
| H-01 | PCB1.J5（DHT11） | **致命** | 针序与市面通用模块完全相反，直插即反接电源 | 需改板 |
| H-02 | PCB1.J6 / J7（MQ） | 严重 | 模块 DO/AO 与板上 AO/空位错开一位，ADC 恒读 0 | 飞线可解 |
| H-03 | PCB1 +5V 主干 | 严重 | J6.1 / J7.1 取不到 5 V，传感器不上电 | 飞线可解 |
| H-04 | GPIO43 | 中等 | 与 UART0 TX 复用，执行器初始化后串口断 | 改脚或改调试口 |
| H-05 | 固件通关态 | 中等 | 答题结束停在通关页无法退出（已修） | 已修复 |

## H-01 致命：J5（DHT11）针序与通用模块相反

**板上针序**（飞针网表实测，从左到右）

| 脚 | 网络 |
|---|---|
| 1 | `GND`（方形焊盘） |
| 2 | `DHT_DATA` → GPIO5 |
| 3 | `+3V3` |

**市面通用 DHT11 模块针序**（HW-487 / KY-015 一类蓝色小板）
`+ S -`，即 `VCC - DATA - GND`，电源在左、地在右。

**两者完全相反。** 直接对插的结果是：

| 模块针 | 落到板上 | 后果 |
|---|---|---|
| `+`（VCC） | 1 脚 GND | 电源接地 |
| `S`（DATA） | 2 脚 DHT_DATA | 侥幸正确 |
| `-`（GND） | 3 脚 +3V3 | 地把 3.3 V 拉低，模块反接 |

**实测现象**：`dht_status=unavailable`，温度与湿度恒显示 `--`；模块无任何指示灯可循（DHT11 模块本身不带 LED），容易被误判成焊接或代码问题。

**风险**：反接后 VCC 与 GND 对调，长时间通电可能损坏模块；同时 3.3 V 被模块地脚直接短路到地，会拉低整条 3.3 V 主干，极端情况下引起主控复位。

**临时对策（首件可用）**

1. 模块**转 180°** 插入，使 `- S +` 对准 `GND - DATA - 3V3`。注意元件面朝下会顶板，需抬高或只插一半。
2. 或用三根母对母杜邦线转接：`-` → J5.1、`S` → J5.2、`+` → J5.3。
3. **不要**尝试正插后再"凑合读"，反接状态下读数是永远拿不到的。

**根治（下一版改板）**

J5 改为 `1 +3V3 / 2 DHT_DATA / 3 GND`，与通用模块一致。仅需调整三个焊盘的网络分配与丝印，不涉及布线层。

## H-02 严重：J6 / J7（MQ）与模块错开一位

**板上针序**

| 脚 | J6（MQ-2） | J7（MQ-135） |
|---|---|---|
| 1 | `+5V` | `+5V` |
| 2 | `GND` | `GND` |
| 3 | `MQ1_AO_5V` → GPIO1 | `MQ2_AO_5V` → GPIO4 |
| 4 | 空（`NET_10`） | 空（`NET_11`） |

**通用 MQ 模块针序**（针脚朝下、元件面朝观察者）
`VCC - GND - DO - AO`

对插结果：

| 模块针 | 落到板上 | 后果 |
|---|---|---|
| VCC | 1 脚 +5V | 正常 |
| GND | 2 脚 GND | 正常 |
| **DO** | **3 脚 AO** | ADC 读到的是数字量输出，清洁空气时为低电平 |
| **AO** | **4 脚空** | 模拟量悬空，无人读取 |

**实测现象**：`mq1.raw=0`、`mq1.adc_mv=0`，且**恒定为 0 不漂移**——这是"读到了稳定的数字低电平"，与"引脚悬空乱跳"可区分。

**对策**：保留 VCC / GND 入孔，把 DO、AO 两针掰开不插，用一根杜邦线把模块 AO 接到板上第 3 脚。

**根治建议**：下一版把 J6 / J7 的第 3、4 脚对调，或直接改为 3 针（`+5V / GND / AO`），省掉悬空的第 4 脚。

## H-03 严重：+5V 主干在板内不通

**现象**：J6.1、J7.1 对 GND 无 5 V，MQ 模块的 `POWER LED` 不亮。开发板侧 J1.21 有 5 V。

**影响**：MQ 两路完全不上电，与 H-02 叠加时表现为"读数恒 0"，无法区分是没电还是读错脚。

**现场处置**：在板子左下、握把上方的备用 5 V 飞线焊盘处短接后恢复（该区域为 R9 遗留的 `J21` / `J22` 备用焊盘）。

**遗留风险**：临时短接的接触可靠性不足，振动或温升后可能掉电，表现是"偶尔读不到"。**正式交付前应改为焊接飞线并用万用表复核通断**。

**根治建议**：复核 `+5V` 从 J1.21 到 J6.1 / J7.1 的走线是否在某处断线或过孔失效；若为设计问题，下一版加宽主干并在末端补测试点。

## H-04 中等：GPIO43 与 UART0 TX 复用

`Board.h` 中 `MotorBin2 = 43`，而 ESP32-S3 的 UART0 TX 默认就是 GPIO43。

`Actuators::begin()` 执行 `pinMode(43, OUTPUT)` 后，UART0 的 TX 功能被普通 GPIO 接管，**串口日志从该时刻起全部失效**。实测表现为启动打印到 `[boot] panel 160x128` 之后彻底静默，屏幕上一切正常，极易误判为固件卡死。

**调试期对策**：编译时加 `-DH2O_KEEP_UART0`，`Actuators.cpp` 会跳过 43 脚的 `pinMode`，保留串口；代价是 B 路 BIN2 不再驱动（执行板未接时无影响）。

**根治建议**：把 B 路 BIN2 换到空闲脚（IO3 / IO46 可用），或让调试走 USB CDC（GPIO19/20），与 UART0 彻底解耦。

## H-05 已修复：通关后停在通关页无法退出（固件）

**现象**：答完最后一题进入通关页后，任何按键都无响应，无法回到菜单，也无法重新开始。

**根因（两处叠加）**

1. `ExamCore.cpp` 的 `Core::start()` 限制只有 `Phase::Menu` 才能开始，通关后 `phase` 为 `Finished`，直接返回空串，报文根本没有发出；
2. 主程序收到空串后**仍然执行了 `switchView(View::Question)`**，于是停在一个没有任何题目的空白答题页，而该页的按键处理只认答题键，返回键没有分支。

**修复**

- `start()` 放行 `Finished`，允许重新挑战；
- `start()` 返回空串时不再切页，改为提示；
- 通关页与空白答题页都补上返回路径（返回键 / OK 键回菜单）；
- 通关后菜单首项文案自动变为“重新挑战”。

**遗留**：服务端是否对同一组开放新一局，取决于服务端实现（当前账号记录为 `level 7 / finished`）。若服务端直接回 `game_over`，板子会立即回到通关页——但不再卡死。

## 复测方法

传感器三路的正确判据（串口 `sensor` 命令）：

- `mq1` / `mq2`：`ao_mv` 应大于 0（数百毫伏量级），对着传感器哈气或凑近酒精棉应明显跳变；`status` 不应长期停在 `uncalibrated` 之外的异常值。
- `dht`：`dht_status` 为 `ok`，温度湿度在 2.5 秒一轮刷新后出现数值。
- 若某一路接好仍恒定 0 或恒定满量程，该模块在先前的反接中可能已损坏，需换件复测。
